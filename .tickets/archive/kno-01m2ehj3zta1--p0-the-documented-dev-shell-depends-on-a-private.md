## Description
Pre-public audit finding, severity P0, from the review workflow over main at fcc6b66 on 2026-09-13. Raised by the docs, hygiene, legal, security, tests lenses and confirmed by an adversarial verifier.

### From the docs lens: The only documented way to run the project depends on a PRIVATE git+ssh Nix input

Evidence: README.md lines 6-17: every invocation is `devenv shell -- knotview ...`; there is no other install path. devenv.yaml:3 `url: git+ssh://git@github.com/krimsonkla/devenv-layers` and devenv.lock:56/60 `ssh://git@github.com/krimsonkla/devenv-layers`. `gh repo view krimsonkla/devenv-layers --json isPrivate,visibility` -> {"isPrivate":true,"visibility":"PRIVATE"}. devenv.nix:5-10 imports three modules from that input, so `devenv shell` cannot evaluate for anyone without SSH access to that private repo (krimsonkla/nix-derivations is PUBLIC and is fine). devenv.yaml also pulls `claude-code-nix` and permits the unfree `claude-code` package, which is tooling unrelated to the project.

Recommendation: Either make devenv-layers public (and switch the input to `github:krimsonkla/devenv-layers` rather than ssh) or make the devenv shell optional: document a plain `uv sync` / `pip install -e .` path in README as the primary route and present devenv as the maintainer's convenience. Drop claude-code-nix from devenv.yaml or document that it is optional.

Verifier (P0, blocks public: yes): Reproduced every piece of evidence: devenv.yaml:3 pins devenv-layers to `git+ssh://git@github.com/krimsonkla/devenv-layers` (devenv.lock:56/60 records the ssh URL, so the lock cannot be resolved without SSH either), `gh repo view krimsonkla/devenv-layers` returns {"isPrivate":true,"visibility":"PRIVATE"} while nix-derivations is PUBLIC, and devenv.nix:5-10 imports three modules from that input, so evaluation of `devenv shell` fails outright for anyone outside the owner's SSH access. README.md lines 7-17 give `devenv shell -- knotview ...` as the only invocation and there is no other install instruction anywhere in README or docs/. Mitigating fact: pyproject.toml has a standard `[project.scripts] knotview = "knotview.entry.console:main"` with three PyPI dependencies and a uv.lock, so `uv sync` / `pip install -e .` followed by `knotview ...` would actually work today; the fix is purely documentation (or making devenv-layers public and switching to a github: input). But because the sole documented path is broken for every outside user on first contact and the README would read as non-functional, P0/blocks_public stands. The claude-code-nix input and `permitted_unfree_packages: [claude-code]` are also present as reported; that part is P2 hygiene, not a blocker.

Evidence: /Users/krimsonkla/git/krimsonkla/knotview/devenv.yaml line 3: `url: git+ssh://git@github.com/krimsonkla/devenv-layers`, locked in devenv.lock at rev 316f630b. `gh repo view krimsonkla/devenv-layers --json isPrivate` returns `{"isPrivate":true}`. devenv.nix imports three modules from that input (lines 5-11), and README.md documents every command as `devenv shell -- knotview ...`; pyproject.toml also relies on devenv's `uv sync`. Recommendation: Either make devenv-layers public (and switch the input to a `github:` URL rather than SSH), or remove the dependency from this repository and document a plain `pip install -e .[dev]` / `uv sync` path plus a note that `knot` must be on PATH. ### From the tests lens: The devenv shell depends on a private git+ssh input, so no outside user can enter the documented environment

Evidence: devenv.yaml line 2-3: `devenv-layers: url: git+ssh://git@github.com/krimsonkla/devenv-layers`. devenv.nix imports three modules from it (`inputs.devenv-layers + "/dev-layers/devenv.nix"`, `/common/devenv.nix`, `/languages/python/3.12.x/devenv.nix`). `gh repo view krimsonkla/devenv-layers --json visibility,isPrivate` returns {"isPrivate":true,"visibility":"PRIVATE"}. Recommendation: Either make devenv-layers public (and confirm its transitive inputs, e.g. nix-derivations, are public; that one is), or make the repository self-contained: replace the layer imports with a plain devenv.nix (python 3.12 + uv, knot, git-hooks) and commit an authored .pre-commit-config.yaml.
