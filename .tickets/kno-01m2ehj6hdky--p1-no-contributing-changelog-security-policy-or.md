## Description
Pre-public audit finding, severity P1, from the review workflow over main at fcc6b66 on 2026-09-13. Raised by the docs lens and confirmed by an adversarial verifier.

### From the docs lens: No CONTRIBUTING, CHANGELOG, SECURITY policy, CODE_OF_CONDUCT, or CI configuration

Evidence: `find . -maxdepth 1 -iname 'CONTRIBUTING*' -o -iname 'CHANGELOG*' -o -iname 'SECURITY*' -o -iname 'CODE_OF_CONDUCT*'` returns nothing; `ls .github` -> no such directory; `git ls-files` confirms none are tracked. The contribution rules that do exist live only in the private devenv-layers hooks and are mentioned in passing in design docs (docs/ai-assistant-ideation/kno-01m2ebf3c8mx-test-coverage-plan.md:28 'the commit-msg hook rejects Co-Authored-By'; :1418 'this repository's ticket-discipline hook blocks bare knot writes'; tests/reading/test_real_knot.py:4-5 same). The audit ticket already notes 'no CONTRIBUTING and no CI'.

Recommendation: Add CONTRIBUTING.md stating: how to set up without devenv, `pytest` (100 percent branch-coverage gate, `-m 'not slow'` when knot is absent), `ruff check`, `pylint`, `black`, the conventional-commit/no-trailer rule and the knot ticket discipline. Add a minimal GitHub Actions workflow running the same. Add SECURITY.md (even if it only says the panel binds loopback and how to report). CHANGELOG and CODE_OF_CONDUCT are P2 but cheap.

Verifier (P1, blocks public: yes): Reproduced in full at fcc6b66: `ls -la` and `git ls-files` show no CONTRIBUTING*, CHANGELOG*, SECURITY*, CODE_OF_CONDUCT*, no .github directory, and zero tracked workflow/.yml files; the only lint/hook configuration is `.pre-commit-config.yaml`, which is a gitignored symlink into /nix/store generated by git-hooks.nix from the `devenv-layers` input, and that input is fetched over `git+ssh://git@github.com/krimsonkla/devenv-layers` (devenv.yaml:2), i.e. private, so an outside contributor cannot even reproduce the hooks that enforce the rules. README.md documents usage only through `devenv shell` and says nothing about tests, lint, commit style, or how to contribute; the conventional-commit/no-trailer rule and the ticket-discipline hook are indeed mentioned only in passing at docs/ai-assistant-ideation/kno-01m2ebf3c8mx-test-coverage-plan.md:28 and :1418 and tests/reading/test_real_knot.py:4-5, exactly as cited. The audit ticket itself (.tickets/kno-01m2ebf5sxdb…:19) already concedes 'no LICENSE, no CONTRIBUTING and no CI'. pyproject.toml does declare the tooling (pytest with --cov-fail-under=100, black, ruff, pylint, a `slow` marker), so the content of a CONTRIBUTING.md is cheap to derive, but nothing tells a first contributor that. The finding is real; P1 is right rather than P0 because the code runs and installs without these files, but a first outside contributor hits the gap immediately (cannot set up without private devenv input, cannot know the commit-msg hook will reject their commit) and there is no CI to catch it, so it does block a credible public launch. Only I would soften the recommendation: SECURITY.md is the least pressing since I verified nothing about binding, and CHANGELOG/CODE_OF_CONDUCT remain P2 polish.
